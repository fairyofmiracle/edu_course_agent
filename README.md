# Студия образовательных программ

Веб-агент для методиста. Слева запрос и файлы, справа документ программы. Ноутбук `notebooks/solution.ipynb` повторяет тот же порядок шагов и читает материалы кейса.

## Запуск

```bash
cd edu-course-agent
cp .env.example .env
```

Модель курса — [Foundation Models в Cloud.ru Evolution](https://cloud.ru/docs/foundation-models/ug/topics/api-ref). В `.env` нужен API-ключ из личного кабинета. Без ключа работают пример, проверка часов и приём файлов. Чат студии берёт модель из `CLOUDRU_MODEL_WRITER`. Строка `CLOUDRU_MODEL` в запрос чата сейчас не подставляется.

```
CLOUDRU_API_KEY=...
CLOUDRU_BASE_URL=https://foundation-models.api.cloud.ru/v1
CLOUDRU_MODEL=ai-sage/GigaChat3-10B-A1.8B
CLOUDRU_MODEL_WRITER=GigaChat/GigaChat-3-Pro
```

Агент сначала собирает каркас: компетенции и учебный план, сумма часов равна объёму. Кнопка «Утвердить каркас» открывает тесты, задания и лекции. Источники агент берёт только из текста методиста и не выдумывает приказы и профстандарты.

```bash
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Если на этом порту открывается другое приложение, студия запускается так: `npx next dev -p 3010`, адрес [http://localhost:3010](http://localhost:3010). Кнопка «Пример 24 ч» показывает заполненную студию без модели.

Проверки часов, брифа и схем инструментов:

```bash
npm test
```

Локальные проверки: `npm test` (31 тест). Живой прогон без браузера:

```bash
npm run dev
# в другом терминале
node scripts/run-cases.mjs 4
# или POST /api/run с { "request": "...", "answers": "...", "references": "..." }
```

Материалы кейса лежат отдельной папкой `materials/`. У каждого документа два файла: исходный `.docx` и текст `.txt`.

- `program-general-24h` — интенсив, 24 часа
- `program-qualification-248h` — стажировка, 248 часов
- `open-cases` — пять открытых запросов и чек-листы

Ноутбук запускается из папки `notebooks` обычным Python, без дополнительных пакетов:

```bash
cd notebooks
jupyter notebook solution.ipynb
```

## Что входит в решение

Статус на 14 октября, после коммита с целыми часами и шаблоном запроса. Сборку живым запросом к модели ещё не прогоняли.

| Что входит в решение | Приоритет | Статус |
| --- | --- | --- |
| Поддержка обоих шаблонов АЦР, любого ИТ-направления и любого объёма часов | Обязательно | Частично. Шаблоны «общеразвивающая» и «повышение квалификации» есть в данных и на экране. Объём до 500 часов, направление задаётся текстом запроса. На модели не проверяли. |
| Прием запроса и референсов в .docx, .pdf и тексте, уточняющие вопросы | Обязательно | Частично. Есть свободный текст, форма шаблона, кнопки «Файл» и «Ссылка». Уточняющие вопросы задаёт модель. Для фразы «примерно месяц» промпт сам ставит 72 часа и запрещает спрашивать объём снова. Открытый запрос 4 требует как раз спросить часы. |
| Карта компетенций, в которой каждая компетенция связана со знаниями, умениями, навыками, темами, вопросами и заданиями | Обязательно | Частично. Поля и связи есть. В примере у компетенций заполнены знания, умения и навыки и есть модули. Не каждая компетенция закрыта вопросом и заданием. |
| Учебный и учебно-тематический план с часами по видам работы и автоматической проверкой сумм | Обязательно | Готово в коде. Часы целые, академические. Сервер дотягивает сумму модулей до объёма минус аттестация. Нулевые лекции и практики не заполняются, если сумма уже сходится: ошибка строки на 248 часах так не копируется. В примере 24 из 24. На модели не проверяли. |
| Тестовые вопросы с ключами и привязкой к результатам обучения | Обязательно | Частично. Ключ у вопроса обязателен, привязка к результату есть в данных. В примере она заполнена у одного вопроса, на экране видна строка «Нет вопроса на результат». |
| Задания для семинаров с критериями оценки | Обязательно | Готово в примере: у заданий есть критерии. Новый комплект агент пишет после утверждения каркаса. |
| Планы лекций и слайды в .pptx хотя бы для одного модуля | Обязательно | Частично. Планы и слайды есть на экране, кнопка «Слайды» скачивает HTML. Файла .pptx нет. |
| Выгрузка программы в .docx по шаблону АЦР | Обязательно | Нет. Кнопки справа скачивают JSON и текст markdown. |
| Отчет автопроверки по часам, покрытию, источникам и полноте разделов | Желательно | Частично. На экране проверяются шаблон, часы, знания-умения-навыки и связь компетенций с модулями. Отдельного отчёта по источникам и полноте разделов бланка нет. |
| Точечная доработка отдельной части без пересборки всего комплекта | Желательно | Частично. Инструмент правки одной секции есть. Правка каркаса снова требует утверждения. Без модели в чате это не прогнать. |
| Выгрузка тестов в формат LMS (GIFT, Moodle XML или CSV) | Желательно | Нет. |
| Актуализация старой программы с поиском устаревших тем и инструментов | Сверх плана | Нет. |
| Адаптация готовой программы под другую аудиторию или другой объем часов | Сверх плана | Нет отдельного сценария. Аудиторию и объём можно поменять в запросе, комплект сам не пересобирается. |

## Что не продумано

Это дыры относительно чек-листов кейса, не относительно вчерашнего коммита.

- Запрос 4. «Примерно месяц» больше не становится 72 часами сам: агент спрашивает, объём и шаблон берутся из ответа методиста. На живом прогоне 14 октября каркас 72 из 72 сошёлся.
- Утренний прогон: есть `POST /api/run` (текст → JSON) и `scripts/run-cases.mjs`. Комплект на все модули дописывается несколькими раундами и ещё нестабилен по полноте.
- Обязательные файлы комплекта не собираются: программа `.docx` по бланку АЦР и слайды `.pptx` хотя бы для одного модуля.
- Каждый результат обучения должен проверяться двумя оценочными средствами. В примере закрыт один результат одним вопросом.
- В `.env` две модели, в чат уходит только `CLOUDRU_MODEL_WRITER`.
- `brief-13-oct.html` — внутренний разбор на вечер 13 октября. Для экспертов 15 октября он уже старый: там ещё написано, что шаблонов и видов часов нет.

## Продуктовый чекпоинт 15 октября

Мягкий отсев. Смотрят бриф и прототип: понят ли методист, ценность каркаса, план по пяти запросам.

Слайды: `checkpoint-15-oct.html`. Прототип — студия с «Пример 24 ч» и живым Cloud.ru. Артефакт сдаётся в систему оператора, не коммитом в git.

### Критерии финала (Магас, до 15 баллов)

| Критерий | Что готовить |
| --- | --- |
| Продуктовая ценность | Каркас снимает 4–8 часов сведения часов и ЗУН. Человек остаётся на «Утвердить каркас», источниках из файлов, приказах и подписи. |
| Реалистичность внедрения | Студия на виртуалке, модели Cloud.ru Evolution. Шаги агента → навыки GigaCowork после хакатона. |
| Питч и ответы | Живой запрос при комиссии. Честно: нет docx по бланку АЦР, нет pptx, нет LMS; комплект дописывается по модулям после утверждения. |

### Запрос 4 (колледж)

Промпт больше не превращает «примерно месяц» в 72 часа сам. Агент сначала спрашивает тип, часы, уровень, форму и аттестацию. Объём и шаблон принимаются только из ответа методиста.

## Что проверить руками

Без ключа Cloud.ru:

1. Открыть студию и нажать «Пример 24 ч». Сверху шаги: Запрос, Каркас, Комплект.
2. На вкладке «Обзор» шаблон — общеразвивающая программа, в таблице часов итог 24 из 24.
3. На «Компетенциях» у узлов есть знания, умения и навыки.
4. На «Плане» у модулей часы разложены на лекции, практику, лабораторные и самостоятельную работу.
5. На «Тестах» у вопроса виден ключ, внизу строка «Нет вопроса на результат».
6. На «Семинарах» у заданий есть критерии.
7. На «Лекциях» открываются слайды. Справа кнопка «Слайды» скачивает HTML. «JSON» и «Текст» скачивают данные и markdown. Кнопок docx и pptx нет.
8. Слева кнопка «Файл»: приложить `materials/program-general-24h.docx`. В блоке референса появляется текст бланка.
9. Справа «Утвердить каркас» сменяет кнопку на «Снять утверждение». Слева вместо «Дособрать каркас» появляется «Собрать комплект». «Снять утверждение» возвращает к каркасу.
10. «Новый курс»: кнопка «Утвердить каркас» не нажимается.
11. В ноутбуке `notebooks/solution.ipynb` проверка часов примера проходит, расхождение строки на 248 часах помечено.

После ключа Cloud.ru:

1. «Новый курс», свободный текст: дырявый запрос из `materials/open-cases` про кибербезопасность. Сейчас промпт, скорее всего, сам поставит 72 часа и не спросит объём. Если так и вышло — это дыра запроса 4, а не сбой ключа.
2. Форма «Шаблон»: повышение квалификации, 72 часа, аудитория и цель. «Собрать по шаблону» должен нарисовать каркас, часы на экране сходятся, тестов ещё нет.
3. После «Утвердить каркас» кнопка «Собрать комплект» дописывает тесты с ключами, семинары с критериями и лекции.
4. Попросить поправить один модуль. Остальные модули остаются на месте, утверждение каркаса сбрасывается.
