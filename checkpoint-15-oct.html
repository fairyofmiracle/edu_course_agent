Методист Академии

Задача бизнеса

Сократить время подготовки программы

Убрать ручные подсчёты, раньше находить ошибки и тратить меньше времени на повторные согласования.

02

Какие требования и ограничения учитываем?

Берём правила из кейса и проверяем их в коде

Что должно быть

  • Два шаблона АЦР: общеразвивающая программа и повышение квалификации.
  • Любое ИТ-направление и заданный объём часов.
  • Входные данные: текст, DOCX и PDF; при нехватке данных — уточняющие вопросы.
  • Документы Минпросвещения, Минобрнауки, Минтруда, 273-ФЗ и профстандарты — только из файлов или проверяемых ссылок.
  • Компетенции → знания, умения, навыки → темы → результаты → оценивание.
  • Тесты с ключами, задания с критериями, планы лекций и слайды.

Что нельзя нарушать

  • Только целые академические часы; сумма модулей и аттестации равна объёму программы.
  • Приказы, профстандарты и источники не выдумываются — только из материалов методиста.
  • Сначала каркас, затем обязательное утверждение человеком, только после этого — полный комплект.
  • Модель планируем подключить через Cloud.ru Evolution, а часы и связи проверять обычным кодом.

Какую ценность получают пользователь и бизнес?

Меньше ручной работы, но последнее слово остаётся за методистом

Для методиста

Не сводить всё вручную

Часы и связи видны на одном экране. Можно поправить один раздел, не переделывая всю программу.

Для Академии

Реже возвращать программы на правки

Одни и те же проверки работают для всех программ. Ошибки в часах и связях видны до согласования.

На пилоте сначала замерим, сколько времени у методиста уходит сейчас, а затем сравним с работой в студии. Цель — получить проверенный каркас не дольше чем за 30 минут.

06

Как устроено решение?

Что происходит между запросом методиста и готовой программой

1 · Уже работает Next.js и React Интерфейс: запрос, файлы, программа, отчёт и выгрузки.
2 · Основа backend Python и FastAPI Оркестратор, обработка документов, API и аудит. Проверки источников уже вынесены в Python.
3 · Генерация Cloud.ru Evolution Модель меняет отдельные разделы через инструменты; подключаем после выдачи доступа.
4 · Данные курса PostgreSQL + pgvector Курсы, версии, связи, история правок и поиск по подтверждённым нормативным материалам.
5 · Файлы Объектное хранилище Исходные DOCX/PDF и готовые DOCX/PPTX; в БД остаются метаданные и ссылки.
6 · Контроль Правила без модели Часы, связи и полнота — кодом. Приказы и профстандарты — только из подтверждённых источников.
Поток данных: интерфейс → Python API → БД и файлы → Cloud.ru → проверка → решение методиста. PostgreSQL и хранилище — следующий этап; мы не выдаём их за уже готовые.
