# Воспроизводимый запуск и E2E-проверка

Инструкция для разработчика и проверяющего «Студии образовательных программ». Основной проверяемый путь — создание **нового курса** в интерфейсе с доступом к разрешённому LLM-шлюзу. «Офлайн-пример» — вспомогательная демонстрация, **не замена** E2E-проверки генерации.

> Основано на `compose.yaml`, `Dockerfile.api`, `.env.example`, `package.json` и существующем `README.md` (состояние материалов на 19.10.2026). Полный запуск в новом окружении и живой запрос к модели при подготовке этого документа не выполнялись.

## 1. Что потребуется

- Git, Docker с поддержкой `docker compose` — для рекомендуемого способа запуска.
- Доступ к одному из двух разрешённых LLM-шлюзов и действующий API-ключ — для проверки реальной генерации моделью.
- Свободный порт **8000** на компьютере с Docker. В Compose наружу публикуется только веб-приложение на `localhost:8000`; FastAPI и PostgreSQL работают внутри сети Compose.
- Для запуска без Docker: Node.js и npm, Python 3.12 (эта версия используется в `Dockerfile.api`), зависимости из `backend/requirements.txt`.

## 2. Получение и настройка ключа

Секреты не добавляются в Git, документацию, скриншоты или сообщения. У проекта есть шаблон `.env.example`.

**Вариант А — шлюз хакатона GigaSchool.** Получите API-ключ в кабинете команды. При запуске на предоставленной VM убедитесь, что в её окружении заданы актуальные переменные `GIGASCHOOL_API_KEY` и `GIGASCHOOL_BASE_URL`.

GIGASCHOOL_API_KEY=<ваш_ключ>

GIGASCHOOL_BASE_URL=https://hub.gigaschool.ru/api/v1/llm/v1

CLOUDRU_API_KEY=

**Вариант Б — Cloud.ru Foundation Models.** Получите API-ключ в своём кабинете Cloud.ru с доступом к Foundation Models. Настройки:

```dotenv
GIGASCHOOL_API_KEY=
CLOUDRU_API_KEY=<ваш_ключ>
CLOUDRU_BASE_URL=https://foundation-models.api.cloud.ru/v1
CLOUDRU_MODEL_WRITER=GigaChat/GigaChat-3-Pro
```

В новой версии проекта используются отдельные переменные для двух разрешённых LLM-шлюзов: `GIGASCHOOL_API_KEY` и `GIGASCHOOL_BASE_URL` для GigaSchool, `CLOUDRU_API_KEY` и `CLOUDRU_BASE_URL` для Cloud.ru. Использование OpenAI-совместимого SDK не означает обращение к `api.openai.com`.

Для одного запуска рекомендуется заполнить только один набор ключей. Если заполнены оба, приоритет имеет Cloud.ru: используется `CLOUDRU_API_KEY`, а ключ GigaSchool не отправляется.

Адрес каждого шлюза проверяется отдельно. Ключ GigaSchool допускается только с `https://hub.gigaschool.ru/api/v1/llm/v1`, а ключ Cloud.ru — только с `https://foundation-models.api.cloud.ru/v1`. Неверная комбинация ключа и адреса или сторонний адрес отклоняются до HTTP-запроса.

Миграции: в Docker Alembic выполняется командой контейнера `api` до старта uvicorn. Локально без Docker сначала `npm run backend:migrate`, и только потом `npm run backend`.

Повторяемый результат сборки — паспорт со штампом: вид программы, объём, аттестация, часы модулей и сходимость плана. Штамп пишет код в проверку, в DOCX и в обзор курса. Переписанный слайд штамп не меняет. Утверждение каркаса запирает этот штамп. Текст лекции — черновик модели: температура запроса 0 не обещает, что две формулировки совпадут слово в слово.

На уже настроенной VM **не перезаписывайте существующий `.env`**. Для локальной копии без готовых секретов:

```bash
cp -n .env.example .env
```

Откройте `.env` в редакторе и внесите свой ключ. При развёртывании вне изолированной тестовой среды измените `POSTGRES_PASSWORD` со значения по умолчанию на уникальный секрет до первого запуска БД; не публикуйте его.

## 3. Рекомендуемый запуск через Docker Compose

В корне клонированного репозитория:

```bash
git clone <URL_репозитория>
cd edu_course_agent
cp -n .env.example .env
# заполните .env, если ключ ещё не настроен
docker compose up -d --build
docker compose ps
```

`<URL_репозитория>` — подставьте адрес фактического репозитория. Не запускайте одновременно локальный FastAPI и Compose на одном порту 8000.

После запуска проверьте командой `docker compose ps`, что сервисы `db`, `api` и `web` работают. Для сервисов, у которых настроен healthcheck, дополнительно проверьте статус `healthy`. При первом запуске сборка и инициализация могут занять время.

- Интерфейс: http://localhost:8000
- Документация FastAPI через прокси: http://localhost:8000/backend/docs

Проверка доступности:

```bash
curl -f http://localhost:8000/
docker compose ps
docker compose logs --tail=100 api
```

При ошибках смотрите `docker compose logs --tail=100 web` и `docker compose logs --tail=100 db`. Логи могут содержать служебные сведения: проверяйте их перед публикацией.

Остановка без удаления данных:

```bash
docker compose down
```

**Не используйте `docker compose down -v` без необходимости:** эта команда удаляет том PostgreSQL и сохранённые данные.

## 4. Миграции базы данных

В Docker сервис `api` зависит от готовности PostgreSQL (`db` с healthcheck). Команда в `Dockerfile.api` выполняет:

```bash
python -m alembic upgrade head && python -m uvicorn backend.app.main:app --host 0.0.0.0 --port 8000
```

Следовательно, **Alembic применяется автоматически перед запуском API**. Если миграции завершатся ошибкой, FastAPI не запустится этой командой. Отдельная ручная миграция при обычном старте Compose не требуется.

Для диагностики:

```bash
docker compose logs --tail=100 api
docker compose exec api python -m alembic current
```

`alembic current` показывает текущую ревизию базы. При необходимости сравните её с `python -m alembic heads` внутри того же контейнера. Не запускайте `upgrade head` одновременно с работающим процессом миграции.

## 5. Альтернативный запуск без Docker

Для локальной разработки из корня репозитория:

```bash
cp -n .env.example .env
# заполните ключ в .env
npm ci
python -m pip install -r backend/requirements.txt
npm run backend:migrate
```

Миграции в этом режиме используют локальную SQLite из `DATABASE_URL=sqlite:///backend/data/studio.db`, если значение не переопределено. Затем запустите **два терминала** из корня проекта:

Терминал 1:

```bash
npm run backend
```

Терминал 2:

```bash
npm run dev
```

- Интерфейс: http://localhost:3000
- FastAPI Swagger: http://localhost:8000/docs

Для локального запуска переменные `PYTHON_AGENT_URL` и `NEXT_PUBLIC_PYTHON_API_URL` должны указывать на `http://127.0.0.1:8000` (как в шаблоне `.env.example`).

## 6. E2E-прогон: от запроса до выгрузки

**Условия:** интерфейс открывается, backend доступен, ключ модели настроен, есть доступ к выбранному шлюзу. Время генерации зависит от ответа модели. Тестируйте через «Новый курс», не через «Офлайн-пример».

| Шаг | Действие проверяющего | Ожидаемый результат |
| --- | --- | --- |
| 1 | Открыть студию и выбрать **«Новый курс»** | Создан новый пустой курс, а не загружен демонстрационный образец |
| 2 | Взять запрос 1 из `materials/open-cases.txt`: «Первые шаги в Python», **16 часов**, школьники 8–9 классов; отправить запрос | Агент формирует каркас образовательной программы с указанной темой и объёмом |
| 3 | Проверить учебный план | Суммарный объём — **16 часов**; программа не наследует часы постороннего образца |
| 4 | Нажать **«Утвердить каркас»**, затем **«Собрать комплект»**, если кнопка показана | Появляются материалы модулей: лекции, практические задания/семинар, тесты и слайды; отсутствие кнопки после заполнения комплекта допустимо |
| 5 | Открыть вкладку **«Проверка»** | Отображаются результаты аудита, в том числе проверка часов и связей результатов обучения с оценочными средствами |
| 6 | Использовать **«Выгрузить → Программа»**, затем **«Презентация»** и **«Данные»** | Скачиваются непустые файлы DOCX, PPTX, JSON с содержанием созданного курса |

**Критерий успешности живого E2E:** каркас и материалы созданы по запросу с использованием настроенной модели, доступны аудит и выгрузки. Если интерфейс сообщает, что текст дописан кодом из-за отсутствия ключа/ответа шлюза, это проверка отказоустойчивости, **не подтверждение полноценной LLM-генерации**.

**Отдельный отрицательный сценарий:** начать ещё один новый курс и отправить неполный запрос про кибербезопасность из `materials/open-cases.txt` (запрос 4, без часов). Ожидается уточнение недостающих параметров, а не самовольная подстановка 72 часов.

**Проверка входных файлов:** в интерфейсе поддерживаются `.txt`, `.md`, `.pdf`, `.docx` с ограничением 8 МБ; проверяйте корректный файл и отклонение неподдерживаемого/пустого. Прямая PDF-ссылка через поле «Ссылка» в текущем защищённом загрузчике не обрабатывается как PDF-документ; для PDF используйте загрузку файла.

## 7. Автоматические проверки и контроль результата

Команды запускаются из корня проекта при установленных зависимостях:

```bash
npm test
python -m pytest backend/tests -q
npm run build
```

`npm run smoke:llm` отправляет реальный запрос к настроенной модели и может расходовать лимиты API. Запускайте его только при необходимости проверки подключения к LLM. Успешный ответ не заменяет полноценный E2E-прогон создания курса. Автоматические тесты и проверка синтаксиса выполняются отдельно, без обращения к модели.

Для воспроизводимого отчёта фиксируйте: дату, commit SHA (`git rev-parse --short HEAD`), способ запуска, `docker compose ps`, наличие ключа (только да/нет), результат миграций, результаты тестов и факт получения трёх файлов. Не сохраняйте значения ключей.

## 8. Типовые неполадки

| Симптом | Что проверить |
| --- | --- |
| `docker compose` не запускается | Установлены Docker и Compose, демон Docker доступен |
| Порт 8000 занят | Остановить локальный FastAPI/другой процесс либо конфликтующий контейнер |
| `db` не становится healthy | `docker compose logs db`, параметры PostgreSQL и том |
| `api` не стартует | `docker compose logs api`; проверить ошибку миграции, доступность БД и конфигурацию |
| Страница открывается, но чат не отвечает | `docker compose logs api` и `web`; доступность разрешённого LLM-шлюза, наличие ключа |
| Генерация заменена резервным текстом | Проверить доступ к модели; резервный результат не считать успешным LLM E2E |
| Не скачивается файл | Проверить статус выгрузки в интерфейсе и логи backend |
